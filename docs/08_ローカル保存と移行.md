# 08. ローカル保存と Supabase 移行（子ドキュメント）

> 親: [00_要件定義書.md](./00_要件定義書.md) ／ 関連: [04_データ設計.md](./04_データ設計.md)

M2（Supabase接続）より前でも「お気に入り」「学習記録」を使えるように、**まず端末ローカル（localStorage）に保存**する方式で先行実装した。アカウント機能が入ったら同じ public API のまま Supabase に差し替える（ローカルファースト設計）。

---

## 1. 現状（キー不要・端末ローカル保存）

| 機能 | 保存場所（localStorage キー） | 実装 |
|---|---|---|
| お気に入り | `cocre:favorites:v1` | [src/lib/userStore.ts](../src/lib/userStore.ts) |
| クイズ成績 | `cocre:quiz-results:v1` | 同上 |

- UI: 図鑑カード／用語詳細のハート（[FavoriteButton](../src/components/FavoriteButton.tsx)）、[マイページ](../src/app/mypage/page.tsx)（お気に入り一覧＋学習記録の可視化）
- クイズ終了時に [QuizRunner](../src/components/QuizRunner.tsx) が成績を記録
- `userStore.ts` の public API（`toggleFavorite` / `recordQuizAttempt` / `useFavorites` / `useQuizAttempts` / `computeStats`）は **Supabase のテーブル構造に1対1で対応**させてある

## 2. 保存データと Supabase テーブルの対応

| localStorage | → Supabase テーブル | 対応カラム |
|---|---|---|
| `cocre:favorites:v1`（slug配列） | `favorites` | `user_id` + `term_slug`, `created_at` |
| `cocre:quiz-results:v1`（配列） | `quiz_results` | `mode` / `score` / `total` / `wrong_slugs` / `taken_at` |

スキーマ本体は [supabase/schema.sql](../supabase/schema.sql)（RLS込み・docs/04準拠）。

## 3. 移行手順（M2で実施）

1. `npm i @supabase/supabase-js`
2. Supabase プロジェクト作成 → `supabase/schema.sql` を SQL Editor で実行
3. `.env.example` を `.env.local` にコピーし `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` を設定
4. [src/lib/supabase/client.ts](../src/lib/supabase/client.ts) の `createBrowserClient()` を有効化
5. `userStore.ts` の読み書きを、ログイン時は Supabase・未ログイン時はローカル、に分岐
6. 初回ログイン時にローカルのお気に入り／成績を Supabase へ**マージ移行**（`upsert`）

## 4. 設計上の注意（docs/CLAUDE.md より）

- 有料コンテンツの出し分けは**必ずサーバー側**で判定する（ローカル保存はあくまで学習の利便性向上用で、権限判断には使わない）
- サブスク状態の正は Stripe 側。`subscriptions` は Webhook（service_role）で同期し、クライアントからは読み取りのみ
