# 12. キャラのアニメ制作方針（次回つづき用・完了したら削除OK）

> このファイルは「次にキャラのアニメをどう作るか」の作業メモ。**方式が決まって実装し終わったら削除してよい。**
> 最終更新: 2026-07-20

## 前提（ユーザーの条件）
- **自分でタイムラインにキーフレームを打つ手作業はしたくない**（コード／仕組みに動かさせたい）。
- **完全無料**でやりたい（Adobe課金があっても手作業ツールAnimate/AEは使わない）。
- クオリティの高いキャラを、アプリ/Webで滑らかに動かしたい。

## 本命プラン：VRoid Studio ×  Three.js（すべて無料）
「自分では動かさない」を満たす王道。

1. **キャラを作る＝VRoid Studio（無料アプリ）**
   - パラメータ調整（プラモ感覚）でアニメ調の高品質3Dモデルが完成。イラストを描いたりパーツ分けする必要なし。
   - 出力＝ **`.vrm`**（すでに骨組み＝リグ入りで"動く状態"）。
2. **モーション（動き）＝Mixamo などの無料モーション**
   - Mixamo（Adobe運営・無料、ユーザーのAdobeアカウントで使える）から「歩く/手を振る/話す」等の `.fbx`/`.gltf` を取得。
3. **動かす＝Three.js / @react-three/fiber（無料）**
   - Claudeへの依頼：「**VRoidの`.vrm`に、ダウンロードした`.fbx`モーションを流し込んで再生するNext.js/Reactコードを書いて**」。
   - 想定ライブラリ：`three` / `@react-three/fiber` / `@react-three/drei` / **`@pixiv/three-vrm`（VRM読み込み）** / VRM用アニメは `@pixiv/three-vrm-animation` か Mixamo→VRMのリターゲット。

## 代替プラン：2D無料イラスト × CSS/JS（GSAP）（すべて無料）
3Dでなくてよいなら最も手軽。
- **素材**：イラストAC / BOOTH 等の**無料キャラ画像（背景透過）**やエフェクト素材を用意（1枚でOK）。
- **動かす**：Claudeへの依頼「**画像をふわふわ浮かせ、正解でエフェクト画像がパッと弾けて消えるCSS+JS（GSAP）を書いて**」。
- 手作業ゼロ、画像1枚だけで軽い。

## 進め方（結論）
クオリティ重視なら → **まずVRoid Studioでベースキャラを作って`.vrm`を書き出し** → それをClaudeに渡してコード配線してもらう、が最短。

## 次回、ユーザーが用意するもの（どちらか）
- [ ] **`.vrm` ファイル**（VRoidから書き出し）← 本命プラン
- [ ] または **使いたいキャラ画像（背景透過PNG）** ← 2Dプラン
- [ ] （任意）動かしたいイメージ／使いたいMixamoモーション名

→ 素材が来たら Claude がコード配線を担当。

## 実装時の注意（Claude用メモ）
- **3D(VRM)は重い**：全ページや**図鑑298カードには載せない**。ヒーロー/ログイン/レッスン等の**限定箇所**に。図鑑カードのミニキャラは今の軽量SVGのまま。
- 既に **Rive実験は導入済み**（`@rive-app/react-canvas`、`/rive-demo`）。今回のVRoid+Three.js路線は**別案の3Dアバター**。最終的にどちらか一本化する（両方入れて重くしない）。
- VRM/Three.js導入時は依存が増える＝バンドル増。**dynamic import＋そのページ限定ロード**にする。
- wasm/大きめアセットは`public/`に置き、必要なら遅延ロード。
